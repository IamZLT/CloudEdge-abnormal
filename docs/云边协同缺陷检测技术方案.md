# 云边协同缺陷检测技术方案

> 面向赛题 XH-202606《面向云边协同场景的分布式人工智能感知与决策关键技术研究》  
> 主场景：工业制造生产线质量检测（缺陷/异常检测）  
> 文档版本：v1.0｜日期：2026-08-01

---

## 1. 背景与目标

### 1.1 赛题定位

赛题要求构建 **「分布式感知 + 云边协同推理 + 全局优化决策」** 体系，解决三类核心矛盾：

| 矛盾 | 表现 | 对缺陷检测的含义 |
|------|------|------------------|
| 实时性 | 全量上云带来带宽与时延瓶颈 | 产线节拍内完成 OK/NG 初判 |
| 可靠性 | 弱网/断网时边缘缺乏自治 | 断网仍可本地质检与告警 |
| 协同性 | 云边算力异构、决策易冲突 | 疑难样本上云精判、模型统一下发 |

工业制造中的 **生产线质量检测** 被列为首要应用方向，与本方案高度对齐。

### 1.2 本方案目标

构建一套可落地的云边协同缺陷检测系统，实现：

1. **边侧轻量推理**：对常见缺陷做毫秒级筛查与初步决策；
2. **云边协同推理**：低置信/难例上云复核，动态选择计算路径；
3. **全局优化闭环**：难例回流标注 → 云端再训练/蒸馏 → 模型按需下发；
4. **弱网可用性**：断网时边侧保持基本质检能力；
5. **多场景验证**：以工业缺陷为主场景，医疗异常检测为第二差异场景，满足「至少 2 类场景」要求。

### 1.3 指标对齐策略（重要）

赛题核心指标段落偏 **大模型（数学/代码/自然语言推理）**，而本项目主任务是 **视觉缺陷检测**。方案采用 **双轨指标**：

| 赛题硬指标 | 本方案映射方式 |
|------------|----------------|
| 边侧保持满血模型 80%–90% 能力 | 边侧轻量检测/异常模型相对云端大模型（或云端强模型）的 Image-AUROC / F1 保留率 |
| TTFT 减少 75% | 边侧视觉推理首帧延迟 vs 云端大模型/全量模型首响应延迟 |
| 单次推理内存 ≤ 1.5GB | 边侧导出模型（OpenVINO/TensorRT/INT8）实测峰值内存 |
| 弱网基本业务功能保持率 ≥ 90% | 断网场景下边侧仍能完成 OK/NG 初判的请求成功率 |
| 平均端到端时延 ≤ 0.2s | 边侧本地路径端到端；协同路径报告 P50/P95 并说明上云占比 |
| 决策冲突 ≤ 5%，解决成功率 ≥ 90% | 多工位/多边缘节点对重叠样本判定冲突率与仲裁成功率 |

视觉任务补充指标：**Image-AUROC、Pixel-AUROC、F1、漏检率、误检率、上云样本比例、带宽节省率**。

## 2. 数据集现状与任务定义

数据根目录：`datasets/`（软链至既有异常检测数据仓库）。

### 2.1 工业主场景（首选）

| 数据集 | 类别数 | 训练集 | 测试集 | 训练异常/正常 | 测试异常/正常 | Mask | 备注 |
|--------|--------|--------|--------|---------------|---------------|------|------|
| **MVTec AD** | 15 | 3629 | 1725 | 0 / 3629 | 1258 / 467 | 1258 | 工业基准；主体分辨率约 1024×1024（目录结构，无 meta.json） |
| **MPDD** | 6 | 888 | 458 | 0 / 888 | 282 / 176 | 282 | 金属零件；统一 1024×1024；有 meta.json |
| **VisA（1cls）** | 12 | 8745 | 2159 | 0 / 8745 | 1200 / 959 | 1200 | PCB/食品等；约 1274×1176–1562×960；有 meta.json |
| **BTAD** | 3 | 1799 | 741 | 主要为 ok | 290 ko / 451 ok | 290 | 约 2540 张图像；ok/ko 命名；含 11 张空 Mask |
| **val/** | — | — | 115 | — | 70 ungood / 45 good | 70 | 本地小验证集（图像 115；含 label 文件更多） |

共性：

- **无监督/半监督异常检测范式**：训练几乎全为 `good/ok`，测试含缺陷与 mask；
- 标注形态分两类：MPDD/VisA/医疗用 `meta.json`（`img_path / mask_path / cls_name / specie_name / anomaly`）；MVTec/BTAD 为目录结构；
- 适合 **Anomalib** 一类异常检测框架直接训练与评估；
- **质量注意**：VisA 存在约 99 张 train/test 重复 good 样本，评估前需清洗；BTAD 定位评估应排除空 Mask。

### 2.2 第二场景（可扩展性）

| 数据集 | 训练集 | 测试集 | 用途 |
|--------|--------|--------|------|
| BrainMRI | 7500 normal | 3715（异常 3075） | 医疗影像异常 |
| LiverCT | 1542 normal | 1493（异常 660） | 医疗影像异常 |
| RetinaOCT | 4297 normal | 1805（异常 764） | 医疗影像异常 |

用于证明方案可迁移到「广域/异构感知」类差异场景，而不必另起一套架构。

### 2.3 任务定义建议

| 阶段 | 任务 | 输入 | 输出 | 说明 |
|------|------|------|------|------|
| P0 | 图像级异常判定 | RGB 图像 | score + OK/NG | 边侧主路径 |
| P0 | 像素级异常定位 | RGB 图像 | anomaly map / mask | 热图可视化、难例筛选 |
| P1 | 缺陷粗分类（可选） | 异常 ROI | 类别（scratch/crack/...） | 有足够标注后启用监督检测 |
| P1 | 云端 VLM 复核（可选） | 图像 + 提示 | 结构化判读/原因 | 对齐「国产大模型」叙事 |

**推荐主任务**：以 MVTec + MPDD + VisA 做 **无监督异常检测 + 云边协同推理**；不必一开始做完整目标检测框标注。

## 3. 现成项目与方案调研（截至 2026-08）

### 3.1 结论先行

| 优先级 | 组合 | 适用条件 |
|--------|------|----------|
| **首选** | **Anomalib + OpenVINO/ONNX Runtime + KubeEdge +（可选）Sedna 联合推理范式 + MLflow + CVAT** | 当前数据以「正常样本训练」为主；Intel/通用边缘；与赛题工业检测最贴合 |
| **备选 A** | PaddleDetection/PaddleX 异常检测 + Paddle Inference + KubeEdge | 强调国产硬件/飞桨生态 |
| **备选 B** | Ultralytics YOLO + TensorRT + KubeEdge | 已有框标注、NVIDIA 产线；需注意 **AGPL-3.0** 合规 |
| **协同增强** | Sedna JointInference / IncrementalLearning；Flower 联邦学习 | 难例上云、多厂隐私训练 |

> 说明：Sedna 官方含 **表面缺陷联邦学习**、**安全帽联合推理（难例上云）** 示例，范式可直接迁移到缺陷检测；但其最新正式版相对 KubeEdge 偏旧，建议 **复用范式与 CRD 思路，业务上不与 Sedna 强绑定**。

### 3.3 可直接复用的官方示例

1. **Sedna Joint Inference（安全帽）**  
   边侧小模型 → Hard Example Mining（IBT/CrossEntropy）→ 难例上云大模型。  
   迁移方式：将置信度/异常分数阈值替换为缺陷检测难例规则。

2. **Sedna Federated Learning（表面缺陷）**  
   多边缘本地训练 + 云端聚合。  
   迁移方式：多产线/多工厂 VisA/MPDD 分片联邦。

3. **Anomalib Deploy（Torch / OpenVINO Inferencer）**  
   训练 → 导出 IR → 边侧推理，形成边侧主路径最短闭环。

## 4. 总体架构

### 4.1 分层设计

```
┌─────────────── 云端（Cloud） ──────────────────────────────┐
│ 全量/大模型复核 │ 训练与蒸馏 │ 决策仲裁 │ 模型注册与下发 │
│ Qwen3-VL / DeepSeek-VL2（可选） + Anomalib 强模型         │
│ MLflow Registry │ CVAT 标注 │ 全局良率与冲突解决           │
└──────────▲───────────────────────────────┬────────────────┘
           │ 难例/特征/分数/缩略图          │ 模型包/策略/阈值
           │ （断网排队）                   │ （KubeEdge 下发）
┌──────────┴─────────── 边侧（Edge） ───────┴────────────────┐
│ 预处理 │ 轻量异常检测 │ 难例挖掘 │ 本地决策 │ 离线缓存     │
│ OpenVINO / ORT / TensorRT │ 内存目标 ≤1.5GB               │
└──────────▲────────────────────────────────────────────────┘
           │ 图像帧 / 传感器
┌──────────┴─────────── 端侧（Device） ──────────────────────┐
│ 工业相机 / 线扫 / 扫码 / PLC 触发                          │
└────────────────────────────────────────────────────────────┘
```

### 4.2 云 / 边 / 端职责

| 层级 | 职责 |
|------|------|
| **端** | 图像采集、触发同步、基础曝光控制；尽量不做重推理 |
| **边** | 预处理、轻量异常检测、OK/NG 初判、难例筛选、弱网自治、结果上报 |
| **云** | 难例精判、跨产线统计、模型训练/压缩/蒸馏、策略与模型下发、多节点冲突仲裁 |

### 4.3 协同推理策略（核心）

对每帧/每件产品：

1. **边侧推理**得到 `score`、`anomaly_map`、时延、资源占用；
2. **难例判定**（任一满足即上云或复检）：
   - `score ∈ [T_low, T_high]`（不确定带）；
   - 异常区域面积/连通域异常；
   - 与历史正常分布漂移过大；
   - 网络良好且任务优先级高；
3. **路径选择**：
   - 易例：边侧直接决策（主路径，目标 ≤ 0.2s）；
   - 难例：上云强模型/VLM 复核，边侧可先给「待复检」；
   - 弱网：强制本地决策，结果入本地队列事后同步；
4. **决策融合**：云结果优先；超时则回落边侧结果并标记「降级」。

该机制直接对应赛题「边缘轻量模型 ↔ 云端全量大模型」与「动态寻优计算路径」。

## 5. 推荐技术选型（落地版）

### 5.1 首选技术栈

| 层次 | 选型 | 理由 |
|------|------|------|
| 边侧感知模型 | **Anomalib**（EfficientAD / PatchCore / PaDiM） | 与现有 meta.json 数据完全匹配；少缺陷样本 |
| 边侧运行时 | **OpenVINO** 或 **ONNX Runtime** | 许可宽松；易控内存；Intel/通用边缘友好 |
| 云端强模型 | Anomalib 更大骨干 +（可选）**Qwen3-VL / DeepSeek-VL2** 复核 | 对齐国产开源大模型叙事；图像缺陷解释 |
| 编排底座 | **KubeEdge** | 断网自治、模型/应用下发成熟 |
| 协同范式 | 自研难例路由（参考 Sedna JointInference） | 避免强绑定 Sedna 版本风险 |
| 数据回流 | 难例队列 + **CVAT** | 只回传难例/ROI，降带宽 |
| 模型治理 | **MLflow Model Registry** | 版本、灰度、回滚 |
| 联邦（可选） | **Flower** | 多厂不出原图时启用 |

### 5.2 边侧模型压缩与内存目标

- 导出：ONNX → OpenVINO IR / TensorRT Engine；
- 精度：FP16 优先，INT8 需用校准集回归漏检率；
- 目标：**单次推理峰值内存 ≤ 1.5GB**；
- 能力保留：相对云端强模型 Image-AUROC / F1 **≥ 80%–90%**。

### 5.3 大模型角色（避免误用）

赛题举例 DeepSeek，但不等于边侧必须跑满血文本大模型。建议：

| 位置 | 模型角色 | 说明 |
|------|----------|------|
| 边侧 | 轻量视觉异常模型为主；可选极小 VLM（如 2B 量化）做结构化输出 | 优先满足内存与时延 |
| 云端 | Qwen3-VL / DeepSeek-VL2 做难例复核、缺陷描述、决策解释 | 体现「云端全量大模型」 |
| 蒸馏 | 用云端 VLM/强模型伪标签或解释，蒸馏边侧分类头/阈值策略 | 形成长周期更新闭环 |

## 6. 关键模块设计

### 6.1 边缘实时感知与轻量化推理

1. 相机帧接入 → Resize / Normalize / 去畸变；
2. Anomalib 轻量模型推理 → `score + map`；
3. 规则引擎：阈值、最小缺陷面积、ROI 屏蔽；
4. 输出：`{product_id, decision, score, latency_ms, mem_mb, hard_flag}`；
5. 本地环形缓存：最近 N 难例图像与特征。

### 6.2 云边协同推理与任务调度

调度输入：

- 网络质量（RTT、丢包、带宽）；
- 边侧负载（CPU/GPU/队列长度）；
- 任务复杂度（score 不确定度、异常面积）；
- 业务优先级（是否关键工位）。

调度输出：`LOCAL | CLOUD_REVIEW | DEGRADED_LOCAL`。

建议实现为可配置策略表 + 在线阈值自适应，而不先上复杂 RL。

### 6.3 全局决策优化与一致性保障

1. **模型更新**：云端按产线/品类训练 → 评估门禁 → MLflow 晋级 → KubeEdge 灰度下发；
2. **冲突检测**：多边缘对同一 `product_id`/时间窗重叠区域结果不一致；
3. **冲突解决**：云端仲裁服务按置信度、模型版本、工位优先级裁决；
4. **目标**：冲突比例 ≤ 5%，解决成功率 ≥ 90%。

### 6.4 数据回流闭环

```
边侧难例 →（压缩 ROI/缩略图）→ 对象存储
        → CVAT 复核标注
        → 训练集增量
        → 云端重训/蒸馏
        → 评估门禁
        → 模型下发边侧
```

原则：默认 **不上传送检全量视频**；仅难例、误报、漏报复核样本。

## 7. 实验与评测方案

### 7.1 基准对比（评审 40 分技术效果必需）

| 方案 | 说明 |
|------|------|
| B0 集中式上云 | 每帧上传云端强模型 |
| B1 单边缘本地 | 仅边侧轻量模型，无上云、无更新 |
| **S 云边协同（本方案）** | 边侧主路径 + 难例上云 + 周期更新 |

对比维度：

1. **实时性**：端到端时延、P95、相对 B0 降低比例；
2. **检测效果**：AUROC / F1 / 漏检率 / 误检率；
3. **资源通信**：上传量、带宽、云端 GPU 利用率；
4. **稳定性**：弱网/断网成功率、可用性；
5. **一致性**：多节点冲突率与仲裁成功率。

### 7.2 数据集划分建议

- 主实验：MVTec（15 类）+ MPDD（6 类）；
- 泛化：VisA/1cls（12 类）；
- 第二场景：BrainMRI 或 RetinaOCT（证明可扩展）；
- 边侧内存与时延：在目标边缘硬件上实测，不用桌面 GPU 数字直接申报。

### 7.3 弱网实验设计

- 注入：带宽限制、高时延、间歇断连；
- 指标：基本业务功能保持率（本地决策成功率）≥ 90%；
- 恢复后：难例队列补传、模型版本对齐。

| **M4 闭环优化** | 2 周 | 难例回流 + CVAT + 再训练；多节点冲突仲裁 |
| **M5 第二场景与赛题指标** | 1–2 周 | 医疗异常迁移；内存/TTFT/弱网/冲突指标成表；演示视频 |

里程碑优先级：**先跑通视觉主路径与协同收益，再补大模型叙事与编排工程化**。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 赛题 LLM 指标与视觉任务不完全同构 | 评审口径争议 | 双轨指标 + 明确映射表；云端引入 VLM 复核 |
| 域漂移（光照/批次/相机位） | 边侧误报升高 | 分品类模型、正常基线监控、阈值自适应 |
| INT8 损伤漏检率 | 质量事故 | 漏检率门禁，不达标禁止晋级 |
| Sedna 文档/版本滞后 | 交付受阻 | 复用范式，自研路由；Sedna 仅作可选增强 |
| Ultralytics AGPL | 合规风险 | 学术演示可用；产品化优先 Anomalib/Paddle |
| MVTec 等数据非商用许可 | 商用受限 | 比赛/科研可用；真实产线需自有数据 |
| 端到端 0.2s 与上云路径冲突 | 指标不达标 | 申报「本地路径平均时延」+ 上云占比；协同路径单独给 P95 |

## 11. 推荐决策（给执行用）

1. **主算法**：Anomalib 无监督异常检测（EfficientAD 优先冲时延，PatchCore 作精度对照）；  
2. **主协同**：难例上云联合推理（Sedna 范式）；  
3. **主底座**：KubeEdge 做应用/模型下发与断网自治；  
4. **主数据**：MVTec + MPDD 打榜，VisA 做泛化，BrainMRI/RetinaOCT 做第二场景；  
5. **国产大模型**：云端 Qwen3-VL 或 DeepSeek-VL2 做复核与解释，不把满血模型硬塞边侧；  
6. **不做**：首期不上完整联邦学习、不上复杂多模型分割生产线；先证明云边相对 B0/B1 的时延、精度、带宽收益。
