> 赛题：XH-202606 云边协同感知与决策  
> 项目：云边协同缺陷检测  
> 详细方案见：[`云边协同缺陷检测技术方案.md`](./云边协同缺陷检测技术方案.md)

## 1. 当前阶段目标

先调研、先跑通 Demo，不要求一次做成完整系统。

本阶段每人/每组完成三件事：

1. **调研**：现成框架能不能直接用（异常检测、边侧部署、云边协同）；
2. **Demo**：在现有 `datasets` 上跑通最小闭环（至少能对一张图给出 OK/NG 或异常分数）；
3. **指标**：按下方清单记录数字，方便后续写报告对比。

推荐技术起点（可调整）：

- 缺陷/异常检测：Anomalib
- 边侧推理：OpenVINO / ONNX Runtime
- 云边协同参考：KubeEdge / Sedna（难例上云）
- 主数据：MVTec、MPDD；扩展可用 VisA、医疗数据集

## 3. 需要报告的指标

报告时统一对比三个方案：

- **B0**：全部上云
- **B1**：仅边侧，不上云
- **S**：边侧为主 + 难例上云（本方案）

### 3.1 赛题硬指标（必须写进报告）

| 指标 | 目标 | 怎么测（口径） |
|------|------|----------------|
| 边侧相对云端能力保留率 | 80%–90% | 边侧 AUROC 或 F1 ÷ 云端同指标 |
| 首响应时延降低 | 减少 75% | 相对云端首响应：`(云-边)/云` |
| 边侧单次推理内存 | ≤ 1.5GB | 实测峰值内存 |
| 弱网基本业务保持率 | ≥ 90% | 断网/高时延时，边侧仍能给出 OK/NG 的比例 |
| 平均端到端时延 | ≤ 0.2s | 至少工业 + 另一场景；报本地主路径平均值，另附上云路径 |
| 多节点决策冲突比例 | ≤ 5% | 冲突数 ÷ 重叠样本数 |
| 冲突解决成功率 | ≥ 90% | 仲裁后达成一致的比例 |

### 3.2 检测效果指标（必须有）

| 指标 | 说明 |
|------|------|
| Image-AUROC | 图像级异常检测主指标 |
| F1 / Precision / Recall | 选定阈值后报告 |
| 漏检率、误检率 | 工业场景重点看漏检 |
| Pixel-AUROC | 有 mask 时尽量报 |

### 3.3 协同收益指标（体现云边价值）

| 指标 | 说明 |
|------|------|
| 上云样本比例 | 上云数 ÷ 总样本数 |
| 带宽/上传量相对 B0 降低 | 证明不全量上传 |
| 时延相对 B0 降低 | 证明比全上云更快 |
| 精度相对 B1 的变化 | 证明难例上云有收益 |

## 4. Demo 验收（本阶段够用即可）

满足以下即可进入下一阶段：

1. 算法：至少 1 个数据集上能训练/推理，并给出 AUROC 或 F1；
2. 边侧：能量化 **时延** 和 **内存**；
3. 协同：能演示「部分样本本地、部分样本上云」；
4. 汇总：有一张 B0 / B1 / S 的指标对比表（先有数，数字可以再刷）。
